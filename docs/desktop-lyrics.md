# 桌面 / Android 悬浮歌词

设置页的歌词卡片仅显示标题、已开启 / 已关闭状态及“设置”按钮。点击“设置”打开歌词设置模态弹窗（Fluent 2 ContentDialog + 分段标签）：标题栏右侧是总开关，下面是一块**实时预览**（直接用当前这句歌词和真实外观渲染），再往下按「常规 / 文字 / 效果」三段分组，页脚左「恢复默认」右「完成」。一次只渲染一段，选项变多也不会把弹窗一路拉长；预览常驻，改颜色/描边/阴影能当场看到结果。关闭歌词后仍可调整外观，穿透选项禁用。所有调整即时生效，“完成”、Esc 或 Android 返回键关闭弹窗；歌词关闭或穿透开启时仍可进入。窄屏 / 横屏内容可滚动，完成按钮固定在底部。

⚠ 弹窗**外壳高度是固定的**（`DialogCard.Height` 由 code-behind 按「外壳可用高度取小、夹在 280~700」算好写死），不跟着当前分段的内容走。三段内容高度差很大（实测常规 668、文字 700、效果 348），交给内容自适应的话点一次标签整张卡片就抽一下——看起来像控件位置在变。固定之后内容多就内部滚动、少就顶部对齐留白；窗口变矮时外壳跟着压，但同样与分段无关。别再把 `Height` 交回内容决定。

写这段时踩过一个坑：`Height` 的初始值是 `NaN`，而 `Math.Abs(NaN - height) > 0.5` **恒为 false**，于是"值没变就不写"的判断一次都没写进去，卡片继续随内容伸缩。必须先 `!double.IsFinite(DialogCard.Height)` 判一次。探针也只比较 `Bounds` 相等是**假阳性**（Grid 的 `*` 行在某些窗口下会把卡片撑成同一高度，看着"没变"），要断言 `dialogCard.Height` 是显式有限值且等于「可用高度 − 外边距」（`--desktop-lyrics` 里 `弹窗高度是显式算好的,不是内容自适应` 那条）。另外真实宿主是 `MainWindowShell` 的 `RowDefinitions="48,*"` 跨两行网格，不是"直接当窗口内容"，探针里复刻了这个结构再验一遍。

⚠ 分段标签的几何必须与"选中哪一段"无关：选中态**只能换颜色，不能改 `BorderThickness`**——曾经只在选中态加 1px 描边，那个按钮就比别家宽 2px（实测 64/62/62），点谁谁变宽、其余按钮跟着横跳。`.tab` 的 `ContentPresenter` 现在每个状态都是 1px 边框，未选中用透明色。三个面板共用同一个 `ScrollViewer`，切段时把 `Offset` 归零，否则在「常规」滚到底再切「效果」会落在半截上。探针里有"切换分段不改变标签位置与宽度"和"切换分段后滚回顶部"两条守着。

在设置 → 桌面歌词开启。Windows 使用独立置顶窗口，主窗口进入托盘后仍显示；Android 首次开启会进入“显示在其他应用上层”授权页面，返回应用后检查授权结果。拒绝授权时关闭开关并显示提示，播放不受影响。

拖动歌词区域可调整位置——**两端都只有歌词本体，没有按钮行**。Windows 早先有一条顶部工具栏（A−/A+/译/背景/穿透/×），已去掉：它会把歌词顶住（窗口 `Y` 到 0 时歌词还差一行才贴顶），而按钮提供的每一项在设置弹窗里都有，总开关 / 翻译 / 穿透还各有一个快捷键（`HotkeyCatalog` 的「桌面歌词」组）。拖动热区现在是整个窗口（`DesktopLyricWindow` 根 `Grid` 的 `PointerPressed`），不是某一条空白带。翻译开关、暂停时隐藏、字号、背景不透明度、穿透开关与各平台位置都保存在配置中。

开启“暂停时隐藏歌词”后，暂停或停止播放会真正收起歌词窗口（不是只调透明度），继续播放时原地显示，隐藏期间不改写歌词总开关。换歌时状态会短暂落到 `Loading`，判定把 `IsPlaying || IsLoading` 一起算作“在播”，否则每切一首都会闪一下。Windows 只 `Hide` 不销毁窗口，位置和穿透样式都保留；Android 摘掉悬浮窗，继续播放时按保存的坐标重建。该开关默认关闭，保持“一直显示”的旧行为。

开启鼠标 / 触摸穿透后，悬浮窗不再接收任何点击（Windows 在 Win32 层加 `WS_EX_TRANSPARENT`）。解除方式只有两个：按桌面歌词穿透快捷键，或回到主应用设置里关掉（动作清单见 `hotkeys.md`）——**窗口上已经没有"穿透"按钮可点，也没有 × 可关**，关歌词同样走快捷键或设置里的总开关。桌面歌词窗口自身也挂着同一套快捷键，因此焦点刚落在它上面时同样能解开，不至于"点不到也按不开"。穿透状态随配置恢复（重启后仍然穿透），只有**关闭歌词**才会连带解除；`DesktopLyricClickThrough` 只在歌词开启时有意义，旧配置里的残留会在加载时归一为 false。Android 12+ 穿透时整体不透明度不超过系统触摸遮挡上限；后台显示复用媒体播放前台服务，服务停止后移除后台悬浮窗。

⚠ 应用退出时 Avalonia 会连带关闭桌面歌词窗口，`Closed` 里不能无脑把 `Enabled` 写回 false —— 否则"开着歌词退出"会被记成关闭，下次启动就不显示。`DesktopLyricController` 用 `Window.Closing` 的 `CloseReason` 区分：只有 `WindowClosing`（用户点 ×/Alt+F4）才算用户关闭，`ApplicationShutdown` / `OwnerWindowClosing` / `OSShutdown` 一律保持原值（实测无 Owner 的独立窗口拿到 `ApplicationShutdown`）。按钮行去掉后 `WindowClosing` 只可能来自 Alt+F4 / 热键，这条判断仍然有效。

（曾经有过一条"穿透时只把 `Toolbar.Opacity` 置 0、高度没有真的让出"的已知红灯，随工具栏一起删掉了：现在 `ClickThrough` 不改任何布局，只动 Win32 样式。）

透明背景下文字带阴影，但任意桌面背景不能保证固定对比度；需要更清晰时提高背景不透明度或开描边。Windows 控件采用现有 Avalonia FluentTheme，Android 使用原生控件；这是 Fluent 风格实现，并非完整 Fluent 2 合规认证。

## 文字外观:字体 / 颜色 / 描边 / 阴影

四条设置都在「文字」「效果」两段里，改动即时生效并落盘（`AppStateStore` 侧字段 `DesktopLyricFontFamily / TextColor / OutlineEnabled / OutlineThickness / OutlineColor / ShadowEnabled / ShadowBlur / ShadowColor`）。颜色一律以 `#AARRGGBB` 存盘，加载时用 `Color.TryParse` 归一，认不出来的值回落到默认（文字 `#FF72E5D3`、描边/阴影 `#FF000000`）。

- **字体家族**：`FontManager.Current.SystemFonts` 枚举本机字体，第一项「跟随系统默认」= 不写局部值（`ClearValue(TextBlock.FontFamilyProperty)` 回继承）。⚠ 别给 `TextBlock.FontFamily` 塞 null，排版里拿不到家族会出问题；列表为空（Headless / 受限平台）只留默认项，不算错误。
- **文字颜色**只作用于主歌词；翻译行固定近白色（`#E6FFFFFF`），主歌词换成任意颜色后主次仍分得开。
- **描边**：Avalonia 没有文字描边原语，公开 API 里只有 `FormattedText.BuildGeometry`，而它不换行（歌词必须换行）⇒ 用 `Controls/DesktopLyricText`：同一段文字在 8 个方向各偏移一层描边色，正文叠在最上面。8 层和正文共享同一格、同一宽度，换行位置天然一致（所以偏移只能写 `RenderTransform`，不能改 `Margin`：外边距会改可用宽度，副本的换行就和正文错开）。关掉描边时副本 `IsVisible=false`，不参与测量。实拍 1.5px / 3px 两档轮廓均匀，没有可见空隙（探针导出 `aly-lyric-outline-{1.5,3.0}.png`）。
- **阴影**：`DropShadowEffect` 挂在歌词容器上（不是每行一个），关掉时 `LyricShadow` 返回 null —— 不挂 Effect 才是真的不画，半径 0 一样要走离屏渲染。

弹窗里的预览和真实窗口绑的是同一份属性，所以不存在"预览跟实际不一致"的可能。预览**按真实字号 1:1 画**（`FontSize` 直接绑过去，别再封顶）：预览板高度在 116~212 之间跟着长，超长行用 `MaxTextLines`（正文 2 行 / 翻译 1 行）+ 省略号收尾。⚠ 不要退回"像素高度硬裁"（那是窗口那边的模式）：大字号下会长歌词裁在半行上，看着像坏了。

## 验证

`dotnet run --project src/ALyricEase.Headless -- --desktop-lyrics`，覆盖异步歌词加载后的时间定位、offset、向后跳转、翻译、切歌清除旧词、设置持久化（含穿透与暂停隐藏）、暂停/继续/换歌加载时的窗口显隐、窗口绑定（含"窗口里没有任何按钮"）、穿透前后歌词屏幕位置与窗口尺寸不变、翻译行受开关控制、关闭歌词连带复位穿透且不残留；以及新弹窗的分段标签（默认段只露一个滑块、切「文字」段能改字号）、**切换分段时弹窗高度与标签几何都不变**（含窗口变矮后的复测）、预览 1:1 跟随字号（不封顶）、描边开关展开/收起粗细滑块、颜色与描边/阴影/字体落盘、恢复默认只回外观不动行为开关。桌面歌词控制器已直接编入 Headless 探针（`csproj` 里 link 源码），显隐走真实控制器而不是测试替身。

系统级置顶、拖动、跨应用穿透以及 Android 授权返回需要真机验收。
