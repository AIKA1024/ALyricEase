# 桌面 / Android 悬浮歌词

设置页的歌词卡片仅显示标题、已开启 / 已关闭状态及“设置”按钮。点击“设置”打开歌词设置模态弹窗，顶部总开关控制开启和关闭，下方集中调整字号、翻译、暂停时隐藏、背景不透明度和穿透。关闭歌词后仍可调整外观，穿透选项禁用。所有调整即时生效，“完成”、Esc 或 Android 返回键关闭弹窗；歌词关闭或穿透开启时仍可进入。窄屏 / 横屏内容可滚动，完成按钮固定在底部。

在设置 → 桌面歌词开启。Windows 使用独立置顶窗口，主窗口进入托盘后仍显示；Android 首次开启会进入“显示在其他应用上层”授权页面，返回应用后检查授权结果。拒绝授权时关闭开关并显示提示，播放不受影响。

拖动歌词区域可调整位置。Windows 的歌词窗口自带按钮行，提供字号增减、背景设置、穿透及关闭（背景按钮打开不透明度滑块）。**Android 悬浮窗只有歌词本体，不再有按钮行**：原先顶部那条 48dp 工具栏会把歌词顶住，窗口 `Y` 到 0 时歌词仍差一行才贴顶；而按钮提供的每一项在设置页的歌词设置弹窗里都有，触屏下长期占位不划算。翻译开关、暂停时隐藏、字号、背景不透明度、穿透开关与各平台位置都保存在配置中。

开启“暂停时隐藏歌词”后，暂停或停止播放会真正收起歌词窗口（不是只调透明度），继续播放时原地显示，隐藏期间不改写歌词总开关。换歌时状态会短暂落到 `Loading`，判定把 `IsPlaying || IsLoading` 一起算作“在播”，否则每切一首都会闪一下。Windows 只 `Hide` 不销毁窗口，位置和穿透样式都保留；Android 摘掉悬浮窗，继续播放时按保存的坐标重建。该开关默认关闭，保持“一直显示”的旧行为。

开启鼠标 / 触摸穿透后，Windows 会把工具栏隐藏，解除方式是按桌面歌词穿透快捷键或回到主应用设置（动作清单见 `hotkeys.md`）。Android 没有工具栏，开启穿透后悬浮窗不再接收触摸，只能在主应用设置的歌词弹窗里关闭穿透（或直接关闭歌词）。桌面歌词窗口自身也挂着同一套快捷键，因此焦点刚落在它上面时同样能解开，不至于"点不到也按不开"。穿透状态随配置恢复（重启后仍然穿透），只有**关闭歌词**才会连带解除；`DesktopLyricClickThrough` 只在歌词开启时有意义，旧配置里的残留会在加载时归一为 false。Android 12+ 穿透时整体不透明度不超过系统触摸遮挡上限；后台显示复用媒体播放前台服务，服务停止后移除后台悬浮窗。

⚠ 应用退出时 Avalonia 会连带关闭桌面歌词窗口，`Closed` 里不能无脑把 `Enabled` 写回 false —— 否则"开着歌词退出"会被记成关闭，下次启动就不显示。`DesktopLyricController` 用 `Window.Closing` 的 `CloseReason` 区分：只有 `WindowClosing`（用户点 ×/Alt+F4）才算用户关闭，`ApplicationShutdown` / `OwnerWindowClosing` / `OSShutdown` 一律保持原值（实测无 Owner 的独立窗口拿到 `ApplicationShutdown`）。

穿透时同时收起工具栏占用的高度并补偿窗口位置，让歌词留在原有屏幕位置；解除时恢复。位置保存使用展开状态的坐标，反复切换不会累积偏移。（⚠ 现状：只把 `Toolbar.Opacity` 置 0，高度没有真的让出，`--desktop-lyrics` 里那条断言仍是红的；要修得把工具栏移出布局并补偿窗口 Y，同时让 `ExpandedPosition` 扣掉偏移。）

透明背景下文字带阴影，但任意桌面背景不能保证固定对比度；需要更清晰时提高背景不透明度。Windows 控件采用现有 Avalonia FluentTheme，Android 使用原生控件；这是 Fluent 风格实现，并非完整 Fluent 2 合规认证。

验证：`dotnet run --project src/ALyricEase.Headless -- --desktop-lyrics`，覆盖异步歌词加载后的时间定位、offset、向后跳转、翻译、切歌清除旧词、设置持久化（含穿透与暂停隐藏）、暂停/继续/换歌加载时的窗口显隐、窗口绑定、关闭歌词连带复位穿透且不残留。桌面歌词控制器已直接编入 Headless 探针（`csproj` 里 link 源码），显隐走真实控制器而不是测试替身。系统级置顶、拖动、跨应用穿透以及 Android 授权返回需要真机验收。
