# 反封号：请求节制与风控规避

> 目标：ALyricEase 是个人音乐播放器，正常使用不应触发网易风控。
> 本文是**实测得来的行为准则**，不是玄学。核心三原则：
> **读多写少、批量合并、低频重试**。

---

## 1. 风控会拦什么（本机实测）

| 行为 | 结果 | 说明 |
|---|---|---|
| 加密 POST（weapi/eapi） | 本机被 WAF 丢弃（HTTP 200 空 body） | 地区级，与加密是否正确无关 |
| 明文 GET `/api/...` | 正常 | 本项目主通道 |
| 海外 IP 拉播放地址 | `url:null` | 地理围栏，非封禁 |
| 匿名频繁注册 | 可能限流 | 本项目 14 天只注册一次 |
| 高频并发批量拉歌单 | 未测到封号，但风险随频率上升 | 见批量合并策略 |

**没有观察到**：明文 GET 低频请求导致封号/限流。封号风险主要来自：
1. 高频爬取（秒级、并发）
2. 登录态下的敏感写操作异常
3. 明显非人类行为（无间隔、全量抓取）

---

## 2. 请求节制策略（ALyricEase 落地）

### 2.1 读多写少

- **播放、歌词、详情、歌单 = 读**，正常节流即可。
- **写操作极少**：本项目只有「红心切换」一个写端点，且依赖用户显式点击。
- 不实现任何「批量点赞」「批量收藏」类功能。

### 2.2 批量合并（关键）

| 场景 | 做法 |
|---|---|
| 批量取曲目详情 | 明文 `/api/song/detail?ids=[...]` 单批 ≤100 首，**绝不逐首请求** |
| 大歌单全量 | v6 一次拿全量 trackIds + 前段；缺的按 ≤100/批 补，**不是一首一首拉** |
| 歌单预览 | 只拉前 N 首（推荐页 6 首），不拉全量 |
| 歌词/播放地址 | 播放到哪首拉哪首，不预取整个歌单 |

一句话：**一次请求换一批数据**，把请求次数压到最低。

### 2.3 缓存

- 匿名 cookie `MUSIC_A` 缓存 14 天，到期才重新注册。
- 红心 id 集合懒加载 + 单飞缓存（`EnsureLikedIdsAsync`），一次加载全局复用。
- 封面图片走独立 `CoverLoader` 缓存（见 `Infrastructure/CoverLoader.cs`）。
- 推荐区块只在前台展示时拉取。

---

## 3. 频率建议（经验值，非官方）

| 操作 | 建议最小间隔 | 说明 |
|---|---|---|
| 匿名注册 | 14 天 | 会话缓存期内不重复 |
| 用户歌单列表 | 会话内 1 次 | 登录时拉一次即可 |
| 歌单详情（v6） | 打开歌单时 1 次 | 滚动增量补批 |
| 歌曲批量详情 | 每批 1 次（≤100/批） | 补缺时调用 |
| 单曲歌词/播放地址 | 播放动作触发 | 不预取 |
| 每日推荐 | 打开推荐页 1 次 | |
| 红心切换 | 用户点击 | 乐观更新 + 失败回滚 |

**自测参考**：`SelfTest.RunAsync` 一次跑完搜索+5首歌歌词+播放地址+2个歌单+推荐区块，
约 20+ 请求、秒级完成，无任何风控。这是安全的上限参考。

## 4. 失败与降级（避免打重试风暴）

### 4.1 双通道回落

- 加密 POST 收到空 body → 置 `_wafBlocked`，**同一会话不再重试加密通道**，直接走明文。
- 这是"发现被拦就换通道"，不是无限重试。

### 4.2 音质降级链

```
hires/lossless → higher → standard   每级只重试 1 次
```
- VIP 曲目明文路径返回 `code -110 / url:null` → **不要再试更高音质**，视为不可播。
- 免费曲拿不到 higher 会再试 standard，仍失败则放弃。

### 4.3 一般请求失败

- 单次 HTTP 超时（本项目 20s）→ 调用方兜底为空态/提示，**不自动重试**。
- 红心加载失败 → 空集合 + 标记，不反复请求（`LoadLikedIdsAsync` catch 后置空）。
- 网络错误与业务错误（`code != 200`）分别处理，业务错误不重试。

## 5. 敏感操作注意事项

### 5.1 播放地址与 IP

- **必带 `X-Real-IP: <随机CN IP>`**：海外 IP 拿不到播放地址；CN IP 池 22 个随机轮换。
- 不要复用真实出口 IP 伪造自己的身份；X-Real-IP 仅用于绕过地理围栏。

### 5.2 Cookie 安全

- `MUSIC_U` 是登录凭证：**不提交仓库、不打全量日志**（`CookieStore.Mask` 打码为 `ab***cd`）。
- 本地明文存储（`%LocalAppData%\ALyricEase\config\cookie.json`）只限当前用户目录。

### 5.3 不要把匿名会话伪装成登录

- 未登录时各接口会返回 `code 301` / 空 / null，**如实降级**（如隐藏每日推荐区块），
  不要伪造登录态去反复试探权限接口。

## 6. 检查清单（新增端点/功能前过一遍）

- [ ] 是 GET 读操作而不是 POST 写操作？（写操作能避免就避免）
- [ ] 是否能批量合并（一次请求换多条数据）？
- [ ] 请求次数是否与用户操作 1:1 对应，而非轮询/预取？
- [ ] 失败时是"降级/放弃"而不是"重试风暴"？
- [ ] 播放地址带 CN `X-Real-IP` 了吗？
- [ ] 登录 cookie 打码了吗？
- [ ] 明文 vs 加密字段名差异（`ar/al/dt` vs `artists/album/duration`）覆盖了吗？
- [ ] 是否需要走明文回落路径？（加密被拦时自动切换）
